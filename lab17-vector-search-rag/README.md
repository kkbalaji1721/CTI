# MongoDB NoSQL Database Lab 17

Independent implementation of Labs 17.1 and 17.2, based on the topics in the
[chapter-17 reference](https://github.com/sujeetjagtap/NoSQL-Databases-using-MongoDB/tree/main/chapter-17).

## What is live versus local

- **Atlas is not configured in this workspace.** `MONGODB_ATLAS_URI` is absent, so no Atlas documents, vector index, or `$vectorSearch` request can be claimed as completed. Set the URI to activate Atlas mode. The code creates a `vectorSearch` index using the selected embedding provider's actual dimensions.
- **Voyage and OpenAI credentials are absent.** The offline RAG uses deterministic 384-dimensional hashed text-feature vectors, not a learned semantic model. The response is explicitly a local demo response, not an LLM completion. Add API credentials to use Voyage and an OpenAI-compatible chat endpoint.
- **Benchmark results are local only.** `benchmark.py` compares scikit-learn IVF with an educational single-layer NSW/HNSW-style graph against exact cosine top-20. It is not an Atlas or production HNSW measurement. Atlas currently exposes vectorSearch indexes through its own supported API; an IVF Atlas index is not claimed or fabricated.

## Requirements and setup (PowerShell)

Python 3.10+ and pip are needed. Docker is optional.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Edit `.env` locally if you have credentials. Never commit or copy it into a
container image. At a minimum:

```dotenv
MONGODB_ATLAS_URI=mongodb+srv://...
VOYAGE_API_KEY=...
OPENAI_API_KEY=...
```

The CLI and Atlas seeding script load `.env` automatically. The file is ignored.
Atlas Vector Search and the LLM/Voyage APIs require network access and valid credentials.

## Run Lab 17.1

```powershell
python app.py
```

Ask questions about the seeded threat reports and enter `quit` to end. Without
an Atlas URI, this runs exact local cosine retrieval and in-process conversation
memory; it does **not** substitute text search for Atlas `$vectorSearch`.
Without an LLM key, it clearly identifies the answer as a local fallback.
Each running CLI process is a separate local conversation session. Ask one
question, then ask `What did I ask you previously?` to see the offline memory
response repeat the prior question. The response is deterministic and explicitly
not generated by an LLM. Each question and response is retained in the session,
and up to five prior messages are sent to the response generator.

Seed/reseed Atlas using stable source/chunk IDs and create its dimension-correct
index:

```powershell
python seed_documents.py
```

Atlas collections: `rag_documents` (text, source, chunk index and embedding)
and `conversations` (last 100 messages per conversation). The RAG prompt
includes the previous five messages.

## Run Lab 17.2

```powershell
python generate_dataset.py
python benchmark.py
```

This creates 5,000 reproducible documents and 384-dimensional local feature
vectors in `results/`, computes exact brute-force top-20 for 100 queries, then
writes `results/comparison.csv` and `results/latency_vs_recall.png`. The CSV
includes the measured average exact-search latency, an exact brute-force
baseline row, and IVF/HNSW-style recall against that exact top-20 ground truth.
The graph includes the exact baseline. Install `requirements.txt` first. The
local vectors are transparent hashed lexical features; they are reproducible
but not pretrained semantic embeddings.

## Docker

The image includes both labs: `app.py` for Lab 17.1 and the benchmark scripts
plus NumPy, scikit-learn, Matplotlib, and ReportLab for Lab 17.2 and report
generation. Benchmark data is generated in the container; it is not baked into
the image.

```powershell
docker build -t mongodb-lab17 .
docker run --rm -it --env-file .env mongodb-lab17 python app.py
docker run --rm -v "${PWD}\results:/app/results" mongodb-lab17 python generate_dataset.py
docker run --rm -v "${PWD}\results:/app/results" mongodb-lab17 python benchmark.py
```

Copy `.env.example` to `.env` first if using the `--env-file` option; credentials
are passed at runtime. `.env`, benchmark output, caches, and source-control
metadata are excluded from the Docker build context. The app uses Atlas only
when `MONGODB_ATLAS_URI` is provided; otherwise it starts explicitly in local
demo mode. The volume mount saves generated benchmark artifacts to the
workspace's `results` folder.

To publish, first authenticate using Docker Desktop or `docker login`, then:

```powershell
docker tag mongodb-lab17:latest kkbalaji1721/mongodb-lab17:latest
docker push kkbalaji1721/mongodb-lab17:latest
```

The Docker Hub repository URL is
